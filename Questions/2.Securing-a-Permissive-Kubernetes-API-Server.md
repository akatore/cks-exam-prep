### The Improved Question

**Scenario: Securing a Permissive Kubernetes API Server**

**Context:**
For testing purposes, a `kubeadm`-provisioned cluster’s API Server was temporarily configured to allow unauthenticated and unauthorized access. The testing is now complete, and the cluster must be secured.

**Task:**
Reconfigure the cluster's API Server to enforce strict authentication, authorization, and admission control. After securing the control plane, clean up any permissive role bindings that were used during the testing phase.

**Requirements:**

1. **Secure the API Server (`kube-apiserver`):**
* Forbid anonymous authentication.
* Set the authorization mode to `Node,RBAC`.
* Enable the `NodeRestriction` admission controller.


2. **Restore Admin Access:**
* *Note:* The cluster uses Docker Engine. Use the `docker` command for troubleshooting container issues if the API server fails to start.
* The current default `kubectl` configuration relies on unauthenticated access and will break once the API server is secured. Use the original admin configuration located at `/etc/kubernetes/admin.conf` to execute further commands.


3. **Clean Up:**
* Delete the `system:anonymous` ClusterRoleBinding to fully remove the testing permissions.



---

### The Solution

The API server in a `kubeadm` cluster runs as a Static Pod. Modifying its manifest file will automatically cause the `kubelet` to restart the `kube-apiserver` container with the new settings.

#### Step 1: Edit the API Server Configuration

Open the `kube-apiserver` static pod manifest in your preferred text editor:

```bash
sudo vi /etc/kubernetes/manifests/kube-apiserver.yaml

```

Locate the `spec.containers.command` section and modify/add the following flags to match the requirements:

```yaml
spec:
  containers:
  - command:
    - kube-apiserver
    # Ensure anonymous auth is explicitly disabled
    - --anonymous-auth=false 
    # Change the authorization mode to Node and RBAC
    - --authorization-mode=Node,RBAC 
    # Ensure NodeRestriction is in the list of enabled admission plugins
    - --enable-admission-plugins=NodeRestriction 
    # ... [keep other existing valid flags like --advertise-address, etc.] ...

```

*Save and exit the file.*

#### Step 2: Wait for the API Server to Restart

Because you modified the manifest, the Kubelet will instantly restart the API server. This can take 30–60 seconds.

Since the existing `kubectl` is about to break, you can verify the container is running using the Docker CLI (as hinted in the requirements):

```bash
sudo docker ps | grep kube-apiserver

```

*Troubleshooting:* If the container isn't running, it means there is a typo in the YAML file. You can check the logs using `sudo docker logs <container-id>`.

#### Step 3: Verify Access Using the Admin Config

At this point, running a standard `kubectl get nodes` will likely result in an "Unauthorized" error because the default context is no longer valid.

Test that the API server is up and accessible using the secure admin config file:

```bash
kubectl --kubeconfig /etc/kubernetes/admin.conf get nodes

```

#### Step 4: Remove the Permissive RoleBinding

Now that you have secure access, clean up the `system:anonymous` binding that was left over from the testing phase. You must pass the `--kubeconfig` flag to authenticate this request:

```bash
kubectl --kubeconfig /etc/kubernetes/admin.conf delete clusterrolebinding system:anonymous

```

**Expected Output:** `clusterrolebinding.rbac.authorization.k8s.io "system:anonymous" deleted`

Would you like me to show you how to back up your current broken `.kube/config` and replace it with the `admin.conf` file so you don't have to type `--kubeconfig /etc/kubernetes/admin.conf` for every command?

Here is how you can replace your broken kubeconfig with the working admin configuration. This is a very common task when fixing or upgrading kubeadm clusters.

By doing this, you set the `admin.conf` as your default context, meaning you won't have to append `--kubeconfig /etc/kubernetes/admin.conf` to every single `kubectl` command.

### Updating Your Default Kubeconfig

Run the following commands in your terminal.

**1. Create the `.kube` directory** *(Just in case it doesn't exist for your current user)*

```bash
mkdir -p $HOME/.kube

```

**2. Back up the existing (broken) configuration**
It's always a good practice to back up the old file before overwriting it, just in case you need to reference it later.

```bash
mv $HOME/.kube/config $HOME/.kube/config.bak

```

*(Note: If you get an error saying the file doesn't exist, you can safely ignore it and move to the next step).*

**3. Copy the admin config to your user profile**
Since `/etc/kubernetes/admin.conf` is owned by root, you will need `sudo` to copy it.

```bash
sudo cp /etc/kubernetes/admin.conf $HOME/.kube/config

```

**4. Change the file ownership**
Because you copied the file using `sudo`, the new config file in your home directory is currently owned by the `root` user. You need to change the ownership to your current regular user so `kubectl` can read it without requiring `sudo`.

```bash
sudo chown $(id -u):$(id -g) $HOME/.kube/config

```

### Verify It Works

Now, test your access using a standard `kubectl` command without any extra flags:

```bash
kubectl get nodes
kubectl get pods -n kube-system

```

If everything is configured correctly, you should see the resources listed without any "Unauthorized" errors!
